🔧 HTTP Methods

HTTP Methods บอก ว่าเราต้องการทำอะไร กับ resource นั้น ๆ ในแต่ละ request

📋 5 Methods หลักที่ต้องรู้
MethodทำอะไรIdempotent?Safe?
GETอ่านข้อมูล✅ ใช่✅ ใช่
POSTสร้างข้อมูลใหม่❌ ไม่❌ ไม่
PUTแทนที่ข้อมูลทั้งหมด✅ ใช่❌ ไม่
PATCHแก้ไขบางส่วน⚠️ ขึ้นกับ impl❌ ไม่
DELETEลบข้อมูล✅ ใช่❌ ไม่

💡 Idempotent = เรียกซ้ำกี่ครั้งก็ได้ผลเหมือนเดิม | Safe = ไม่เปลี่ยนข้อมูลบน server

🎮 Interactive: เลือก Method ให้ถูกต้อง

ลากหรือกดเลือก Method ที่เหมาะกับแต่ละ action

📝 ตัวอย่างโค้ด Express.js

// ออกแบบ Route สำหรับ User resource
const express = require('express')
const router = express.Router()

// GET  — ดึงรายการ users ทั้งหมด
router.get('/users', getAllUsers)

// GET  — ดึง user คนเดียวด้วย id
router.get('/users/:id', getUserById)

// POST — สร้าง user ใหม่
router.post('/users', createUser)

// PUT  — อัปเดตข้อมูลทั้งหมดของ user
router.put('/users/:id', replaceUser)

// PATCH — แก้ไขแค่บางฟิลด์ของ user
router.patch('/users/:id', updateUser)

// DELETE — ลบ user
router.delete('/users/:id', deleteUser)

🔗 URL Design (Naming Conventions)

URL ที่ดีทำให้ API อ่านรู้เรื่อง ไม่ต้องอ่าน Docs ก็เดาได้

✅ กฎที่ดีของ URL
  • ใช้ คำนาม (noun) ไม่ใช่กริยา: /users ✅ ไม่ใช่ /getUsers ❌
  • ใช้ พหูพจน์ (plural): /products ✅ ไม่ใช่ /product
  • ใช้ kebab-case ถ้ามีหลายคำ: /blog-posts
  • ใช้ nested resource สำหรับความสัมพันธ์: /users/42/orders
  • ไม่ต้องใส่ version ใน URL ถ้าไม่จำเป็น แต่ถ้าใส่ให้ใช้ /v1/...
  • ใช้ query string สำหรับ filter, sort, paginate

❌ vs ✅ ตัวอย่าง URL ที่ดีและไม่ดี

    📡 HTTP Status Codes

    Status Code คือ การสื่อสารจาก Server ถึง Client ว่าเกิดอะไรขึ้นกับ Request ของคุณ

    🗂️ กลุ่มหลัก 5 กลุ่ม
    กลุ่มความหมายตัวอย่าง
    2xxสำเร็จ200 OK, 201 Created, 204 No Content
    3xxRedirect301 Moved Permanently, 304 Not Modified
    4xxClient Error400 Bad Request, 401, 403, 404, 422, 429
    5xxServer Error500 Internal Server Error, 503 Unavailable

    🎯 Match Status Code — จับคู่ให้ถูก

    กดสถานการณ์ แล้วเลือก Status Code ที่ถูกต้อง

    📦 Request & Response Structure

    การออกแบบ body ของ request และ response ให้ สม่ำเสมอ (consistent) คือหัวใจของ API ที่ดี

    📤 Request Headers ที่สำคัญ
    Headerค่าตัวอย่างใช้ทำอะไร
    Content-Typeapplication/jsonบอกว่า body เป็น JSON
    AuthorizationBearer <token>ส่ง JWT token เพื่อ auth
    Acceptapplication/jsonบอกว่าอยากได้ response เป็น JSON
    X-Request-IDuuid-stringติดตาม request สำหรับ debug

    📐 Response Body มาตรฐาน

    การกำหนด format ที่สม่ำเสมอช่วยให้ Frontend ทำงานง่ายขึ้นมาก

    // ✅ Response สำเร็จ (Single resource)
{
  "success": true,
  "data": {
    "id": 42,
    "name": "สมชาย ใจดี",
    "email": "somchai@example.com"
  }
}

// ✅ Response สำเร็จ (List + Pagination)
{
  "success": true,
  "data": [...],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 150,
    "totalPages": 8
  }
}

// ✅ Response เมื่อเกิด Error
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "email ไม่ถูกต้อง",
    "details": [
      { "field": "email", "issue": "invalid format" }
    ]
  }
}

    กรอกข้อมูลแล้วกด สร้าง Response เพื่อดูตัวอย่าง JSON response ที่ได้
