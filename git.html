Git คืออะไร?

Git คือ ระบบจัดการเวอร์ชัน (Version Control System — VCS) ที่ช่วยให้คุณ:

  • ☐ บันทึกประวัติการเปลี่ยนแปลงโค้ดทุกครั้ง
  • ☐ ย้อนกลับไปสถานะก่อนหน้าได้ทุกเมื่อ
  • ☐ ทำงานร่วมกับทีมโดยไม่ทับโค้ดกัน
  • ☐ ทดลองฟีเจอร์ใหม่ใน branch แยกได้ปลอดภัย

👆 กดแต่ละข้อเพื่อ mark ว่าเข้าใจแล้ว

💡
เปรียบเทียบแบบง่าย
Git เหมือน "Save Game" ในวิดีโอเกม — คุณ save ได้บ่อยแค่ไหนก็ได้ และกลับมาจุดที่ save ได้เสมอ แม้จะตายหรือพลาดก็ไม่ต้องเริ่มใหม่ตั้งแต่ต้น

Git vs GitHub ต่างกันอย่างไร?

Git ≠ GitHub
🛠️
Git
โปรแกรม / เครื่องมือ
ทำงานบนเครื่องคุณ
ติดตามการเปลี่ยนแปลง
☁️
GitHub
เว็บไซต์ / Cloud
เก็บ repository ออนไลน์
ทำงานร่วมกับทีม

Git = เครื่องมือที่ใช้จัดการ  |  GitHub = พื้นที่เก็บโค้ดออนไลน์

ตั้งค่า Identity (ทำครั้งเดียว)

Git ต้องรู้จักตัวตนของคุณ เพื่อบันทึกว่า commit นี้ทำโดยใคร:

Terminal
# ตั้งชื่อ git config --global user.name "Your Name" # ตั้งอีเมล (ใช้อีเมลเดียวกับ GitHub) git config --global user.email "you@example.com" # ตรวจสอบการตั้งค่า git config --list
⚠️
ใช้ อีเมลเดียวกับที่สมัคร GitHub เพื่อให้ commit ของคุณแสดงในโปรไฟล์อย่างถูกต้อง

🐙 Step 5 — GitHub คืออะไร?
สร้าง Repository บน GitHub ครั้งแรก
▼

GitHub คือ Cloud Platform ที่เก็บ Git repository ของคุณออนไลน์ ทำให้:

  • โค้ดไม่หายแม้เครื่องคุณพัง
  • ทำงานร่วมกับทีม/เพื่อนได้จากทุกที่
  • แสดง Portfolio ให้ HR/ลูกค้าดูได้
  • รับ contribution จาก Open Source community

สร้าง Repository ครั้งแรก (Step-by-step)

1
เข้า github.com และ Login (สมัครฟรีถ้ายังไม่มีบัญชี)
2
กดปุ่ม "New" (สีเขียว บริเวณด้านซ้ายมือ)
3
ตั้งชื่อ Repository เช่น my-first-repo — เลือก Public หรือ Private
4
กด "Create repository" — เสร็จแล้ว! 🎉
✅
เคล็ดลับ: ตั้งชื่อ repository ให้สื่อความหมาย เช่น portfolio-website, todo-app — ไม่ใช่ asdf123 😅

Workflow: เชื่อม Local กับ GitHub (ครั้งแรก)

Terminal
# 1. เริ่มต้น Git (ถ้ายังไม่ได้ init) git init # 2. Stage ทุกไฟล์ git add . # 3. Commit ครั้งแรก git commit -m "first commit" # 4. เชื่อมกับ remote (GitHub) git remote add origin https://github.com/username/my-first-repo.git # 5. Push ขึ้น GitHub ครั้งแรก (-u ตั้ง upstream) git push -u origin main

git push — ส่งโค้ดจากเครื่องขึ้น GitHub

Terminal
# Push ไปยัง branch main git push origin main # ครั้งแรกใช้ -u เพื่อ set upstream (ครั้งต่อไปพิมพ์แค่ git push) git push -u origin main

git pull — ดึงโค้ดล่าสุดจาก GitHub มาที่เครื่อง

Terminal
# Pull โค้ดล่าสุดจาก GitHub git pull origin main # ถ้า set upstream ไว้แล้ว ใช้แค่นี้ git pull
🌍 Real-world Use Case
เพื่อนร่วมทีม push โค้ดใหม่ขึ้น GitHub
ก่อนเริ่มทำงานทุกเช้า ให้ git pull เสมอเพื่อให้มีโค้ดล่าสุดในเครื่อง และหลีกเลี่ยง conflict

git clone — คัดลอก repository จาก GitHub ลงเครื่อง

Terminal
# Clone repo ลงโฟลเดอร์ใหม่ git clone https://github.com/username/repo.git # จะได้โฟลเดอร์ repo/ โดยอัตโนมัติ cd repo

🌿 Step 7 — Branching (สาขา)
แยก branch ทำฟีเจอร์ใหม่โดยไม่กระทบ main
▼
💡
Branch คืออะไร?
คิดว่า branch เหมือน "เส้นทางขนาน" ของโค้ด — คุณทำงานบน branch ใหม่โดยไม่กระทบ main จนกว่าจะพร้อม merge
Branch Visualization — main & feature/login

คำสั่ง Branch ที่ใช้บ่อย

Terminal
# ดู branch ทั้งหมด (* = branch ปัจจุบัน) git branch # สร้าง branch ใหม่ git branch feature/login # สลับไปยัง branch นั้น git checkout feature/login # ⚡ สร้าง + สลับในคำสั่งเดียว (แนะนำ!) git checkout -b feature/login # เมื่อทำงานเสร็จ: กลับ main แล้ว merge git checkout main git merge feature/login # ลบ branch หลัง merge เสร็จ git branch -d feature/login
🌍 Real-world Use Case
ทีม 3 คน ทำงานพร้อมกันโดยไม่ชนกัน
• นัท: feature/navbar — ทำ Navigation bar
• มิ้น: feature/login — ทำระบบ Login
• โบ้: fix/mobile-layout — แก้ layout หน้า Mobile
ทำงานพร้อมกัน 3 คน แล้วค่อย merge รวมกันตอนสิ้นวัน

🗺️ Standard Git Workflow สมบูรณ์

Standard Daily Workflow
# === เริ่ม project ใหม่ === mkdir my-project && cd my-project git init git remote add origin https://github.com/you/my-project.git # === ทำงานทุกวัน === git pull # ดึงโค้ดล่าสุดก่อนทำงาน git checkout -b feature/navbar # สร้าง branch ใหม่ # ...แก้โค้ด... git status # ดูอะไรเปลี่ยน git add . # Stage ทุกอย่าง git commit -m "feat: add navbar" # Commit git push origin feature/navbar # Push ขึ้น GitHub # === Merge กลับ main === git checkout main git merge feature/navbar git push origin main

🚀 ขั้นตอนถัดไปหลังจบบทเรียนนี้

  • ☐ สร้าง GitHub account และ repository แรกของคุณ
  • ☐ Push โปรเจกต์ปัจจุบันขึ้น GitHub
  • ☐ ลองสร้าง Pull Request ครั้งแรก
  • ☐ เรียนรู้ .gitignore เพื่อ exclude ไฟล์ที่ไม่ต้อง track (เช่น node_modules)
  • ☐ ลอง Fork และ contribute ใน Open Source project เล็ก ๆ
